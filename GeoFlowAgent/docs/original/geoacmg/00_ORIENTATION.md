# 방향성 — 이 실험이 무엇을 묻고, 왜 이렇게 생겼는가

> 코드를 처음 여는 사람이 30분 안에 "왜 이 설계인가"까지 이해하도록 쓴 문서입니다.
> 실행 방법은 `README.md`, 단계별 절차는 `02_STEP_GUIDE.md`에 있습니다.

---

## 한 문단

**동결된 언어모델의 임베딩 공간이 도구 워크플로의 실행 구조를 담고 있는가**, 그리고 담고 있다면
**그 공간 위에서 계획을 생성하는 것이 도구를 하나씩 고르는 것보다 나은가.** 이 둘을 실제 임상유전학
문제 위에서 검정합니다. 두 질문은 별개가 아니라 **한 주장의 두 면**이고, 그 연결 자체가 측정 대상입니다.

---

## 1. 두 질문

원래 문장 그대로:

> **Q1.** Frozen Model을 사용한 임베딩 스페이스를 사용할 수 있을까? 그리고 이 임베딩 스페이스가
> 유효함을 어떻게 증명할까?
>
> **Q2.** 그렇게 만든 임베딩 스페이스에서 생물학적인 정보가 들어있는 실제 데이터와 Tool을 사용해서
> FlowAgent가 가능한지 보자. (…) 그리고 이것은 그냥 Tool을 나눠서 사용하는 것보다 실제 정답에 더
> 근접하게 다가갈 수 있는지. **FlowAgent가 유효한지. 이는 곧 임베딩 스페이스의 유효함으로 직결되기도 하지.**

마지막 문장이 이 논문의 **논지**입니다. 계획 생성기가 값을 하는 것은 그것이 서 있는 표현이 실행
기하를 담고 있을 때뿐이라는 것. 그래서 Q1과 Q2를 따로 보고하지 않고, **둘의 연결을 측정합니다.**

---

## 2. 왜 아직 열린 질문인가

이 연구는 latent flow planning 계열에서 **의도적으로 파생**되었습니다. 계보가 명확한 편이 낫습니다 —
리뷰어의 질문이 "새로운가"에서 <b>"추가한 부분이 실제로 일을 하는가"</b>로 바뀌고, 후자는 실험으로
답할 수 있기 때문입니다.

이 계열의 시스템은 다섯 축으로 분해됩니다. 선행 연구는 이 공간의 **점**입니다.

| | 인코더 | 계획 점수 | 생성기 | 커밋 | 재계획 |
|---|---|---|---|---|---|
| **FlowAgent** (2605.07339) | 전부 학습 | 손으로 지정한 utility | flow | 1 | 매 스텝 |
| **LeFlow** (2608.24855) | **동결** | **raw L2** | rectified flow | 5 | receding horizon |
| *Latent Geometry Beyond Search* (2605.08732) | **동결** | — | amortized 한 방 | 1 | 매 스텝 |
| **우리** | **동결** | **학습된 거리 기하** | flow | **?** | **?** |

**비워진 자리가 정확히 하나입니다 — "동결 표현 위에 학습된 goal-conditioned 거리 기하".**
FlowAgent는 인코더를 전부 학습시키고 거리 대신 손으로 만든 점수를 씁니다. LeFlow는 동결이지만
목표까지의 랭킹이 raw L2입니다.

문헌 조사 결과 **아무도 하지 않은 것**이 넷 더 있습니다.

1. whole-plan 대 step-wise의 **compute-matched 비교** (NFE는 보고되지만 성능을 같은 예산에서 자르지 않음)
2. LLM agent tool workflow에서의 **quasimetric 기하** (quasimetric RL은 전부 연속 제어에만)
3. **동결 생의학 임베딩이 workflow 진행도·가용 행동을 담는지**에 대한 측정
4. **실제 임상유전학 도구 + step-level 정답**을 가진 벤치마크

## 3. 1차 실험이 알려준 것

합성 데이터(hard-v2, 240 task)로 끝까지 돌린 결과가 이 설계의 출발점입니다.

| 결과 | 숫자 | 이번 설계에 준 영향 |
|---|---|---|
| **metric 교란** | frozen-cosine − hash-**Euclidean** = +0.048. metric을 맞추니 **−0.0009**로 소멸 | 모든 표현 주장에 **거리함수·파라미터 동시 정합** 통제를 붙임 |
| **뷰 역할 분리** | Qwen이 진행도(Spearman 0.818), MedCPT가 행동 판독(ridge 0.347). 단순 이어붙이면 **오히려 나빠짐** (0.622 < 0.772) | 역할 배정을 train 측정으로 자동 결정하는 융합을 검정 |
| **DNABERT-2·SapBERT 붕괴** | 둘 다 contract-only 바닥(0.358) | 유전자 이름이 `SYNG0004`, 서열이 무작위 96nt였음 — **인코딩할 게 없었음.** 이번에 처음 공정한 시험 |
| **복잡한 기하 패배** | order violation 0.476, Poincaré 0.573 < cosine 0.622. 방향 파라미터는 실제로 학습됨(norm 0.040–0.119) | 9종 재탕 대신 **왜 졌는지**를 검정 |
| **재계획 > one-shot** | 0.700 vs 0.349, compute-matched blind는 0.050 | 통제를 유지하되 헤드라인에서 내림 |
| **DAgger 무효** | 세 지표 CI 전부 0 포함 | 기본 파이프라인에서 제외 |
| **데이터가 작음** | "유효 독립 단위는 task 144개에 가깝다" | 독립 단위를 **유전자**로 두고, 유효 클러스터 수를 명시 |

그리고 스스로 적어둔 구멍 하나: *"명시적 minimal-pair corpus가 없어 해당 intrinsic 항목은 아직 0개다."*
→ 이번에 실제 ClinGen 기록으로 채웠습니다(표기 불변 12,960쌍, 반대 분류 471쌍).

## 4. 왜 임상유전학인가

FlowAgent가 의미를 가지려면 task가 두 조건을 **실제로** 만족해야 합니다.

```
(1) 도구 다양성이 필요할 것      도구 하나로 풀리면 계획할 게 없다
(2) 단계별 성과가 정의될 것       각 스텝이 답에 얼마나 다가갔는지 잴 수 없으면
                                "계획이 좋다"가 종점 성공률 하나로 뭉개진다
```

임상 변이 해석은 셋을 동시에 만족하는 드문 영역입니다.

**도구 다양성이 데이터에 강제되어 있습니다.** 변이 하나를 분류하려면 근거 코드를 모아야 하는데,
코드마다 봐야 할 데이터베이스가 다릅니다 — PM2·BA1은 gnomAD, PP3는 AlphaMissense, PVS1은
Ensembl VEP + NMD 위치 + ClinGen dosage, PM3는 ClinVar, PP4는 HPO. **단일 도구군으로 도달 가능한
정확도는 0.275, 전체는 1.0, 격차 0.725 [0.670, 0.775]** — 측정값입니다.

**전문가가 단계별로 무엇을 했는지 기록이 남아 있습니다.** ClinGen Evidence Repository가 변이
13,278건에 대해 <b>적용한 코드(Met)와 검토 후 기각한 코드(Not Met)</b>를 CC0로 배포합니다.
"단계 정답을 하드코딩한다" 대신 **사람 전문가의 실제 작업 기록**을 씁니다.

**정답이 공개되어 있습니다.** 패널의 최종 분류가 종점 정답입니다.

> **Not Met이 이 데이터의 숨은 핵심입니다.** 전문가가 "검토했고 기각했다"고 남긴 코드 =
> **불렀지만 0점이었던 도구.** Met만 보면 "정답 도구만 부르는" 정책이 최적처럼 보이는데,
> 실제로는 어느 코드가 설지 부르기 전에 모릅니다. 스냅샷의 **34.1%가 `none_met`** — 호출 3번 중
> 1번은 비용만 쓰고 0점입니다.

## 5. "단계별 성과"를 어떻게 정의했는가 — 설계의 급소

여기가 제가 직접 정했다면 논문이 무너졌을 지점입니다. 유전학 문헌에 정확히 그 역할을 하는
**공표된 체계**가 있습니다.

**Tavtigian et al. 2020** (*Hum Mutat* 41:1734), 곧 나올 ACMG SVC v4의 기반:

```
근거 강도 → 점수      Supporting ±1 · Moderate ±2 · Strong ±4 · Very Strong ±8 · BA1 = −8

총점 → 분류          ≥10  Pathogenic
                     6~9  Likely Pathogenic
                     0~5  VUS
                   −6~−1  Likely Benign
                     ≤−7  Benign
```

이게 네 가지를 한꺼번에 줍니다.

| | |
|---|---|
| **상태마다 잠정 답이 있다** | 궤적이 곧 잠정 분류의 수열. 전문가 결론으로 수렴하는지 매 스텝 관측 |
| **비용 대비 성과가 무차원** | `스텝 효율 = Δ점수 / 측정된 비용`. 제가 정한 상수 0개 |
| **STOP이 임의 임계값이 아님** | 점수가 밴드를 확정하면 멈춤. 1차의 `[0.1,0.3,0.5,0.7,0.9]` 격자를 버림 |
| **목표 기하가 도메인에서 나옴** | 거리 = 분류 확정까지 남은 **근거의 양**. 임상적 의미가 있는 양 |

**검증**: 점수 체계가 전문가 분류를 **0.9493** 재현합니다(12,995건). 이게 높아야 진행도 지표로 쓸
근거가 됩니다. 필터로는 쓰지 않고 보고만 합니다.

### 부수 효과 — C4의 근거가 도메인에서 나온다

**근거는 쌓이기만 합니다.** 이미 확인한 gnomAD 빈도를 "안 본 것으로" 되돌릴 수 없습니다.
상태 전이가 단조 누적이고 도달 관계가 부분순서입니다. **대칭 거리는 이 구조를 표현할 수 없습니다.**

1차에서 비대칭 계열이 진 이유는 그때 fixture가 **평평한 증거 더미**였기 때문입니다 — 순서는 있었지만
그 순서가 분류 의미를 나르지 않았습니다. 여기서는 **순서가 곧 점수이고 점수가 곧 분류**입니다.
문헌도 같은 방향입니다: TMD/MQE는 quasimetric 이득이 **비대칭·장기지평·경로 조합**에 집중되고
조밀·대칭·단기에서는 사라진다고 보고합니다.

> **정직한 수정 하나.** 계획서 v3는 조절변수로 "비가역성 ρ"를 제안했는데, 이 도메인에서는
> **모든 전이가 비가역이라 ρ에 분산이 없습니다.** 회귀가 성립하지 않습니다. 대신 분산이 실재하고
> 문헌 예측이 붙는 <b>지평 길이(필요 도구군 수, 1~4)</b>를 조절변수로 씁니다. δ-hyperbolicity도
> 상태 그래프가 하이퍼큐브라 task 간 분산이 없어 조절변수에서 뺐습니다 — hyperbolic은 단순 비교
> arm으로만 남깁니다.

## 6. 주장 다섯과 반증 조건

각 주장에는 **그것이 틀렸을 때 나오는 관측**이 붙어 있습니다. 임계값은 없습니다.

| | 주장 | 반증되는 관측 |
|---|---|---|
| **C1** | 동결 임베딩이 남은 실행 비용과 다음 최적 행동 정보를 담는다 | **거리함수·파라미터 동시 정합** 무작위 특징 통제와 짝지은 CI가 0을 포함 |
| **C2** | 그 정보는 표면 절차가 아니라 **생물학**이다 | 반사실 실체교체에 행동이 반응하지 않음 / 최소쌍 분리가 귀무분포 안 / 오염 홀드아웃에서 이점 소멸 |
| **C3** | 계획 생성이 같은 기하 위 탐욕보다 낫다 (동일 도구 비용) | k-커밋 곡선의 최적이 k=1 / 비용 정합 탐색이 따라잡음 |
| **C4** | 비유클리드 기하의 이득은 task의 **측정된 구조**로 예측된다 | 조절변수 회귀 기울기 CI가 0 포함 |
| **C5** | **C1–C2와 C3는 연결되어 있다** | 거리 헤드를 빼도 flow 이점이 안 줄거나, 용량-반응 기울기 CI가 0 포함 |

**C5를 어떻게 측정하는가** — 논지를 검정하는 부분입니다.

```
개입        거리 헤드를 raw L2로 교체       → flow 이점이 줄거나 사라져야
용량-반응   task별 기하 정렬 품질 위로       → 기울기 > 0 이어야
            task별 flow 이점을 회귀
뷰 간 복제  뷰마다 정렬 품질이 다름          → 뷰별 flow 이점이 그 순위를 따라가야
            (1차: Qwen 0.818 vs MedCPT 0.419)
```

개입은 인과적, 용량-반응은 그 인과가 우연이 아님을, 뷰 간 복제는 단일 데이터셋 우연이 아님을
보입니다. **셋이 같은 방향이면 두 질문이 하나였음이 측정된 것입니다.**

## 7. 각 단계가 무엇을 사는가

```
  prereg     주검정을 미리 못 박음         사후에 가장 큰 효과를 헤드라인으로 못 올림
     │
  corpus     ClinGen → task                정답을 만들지 않고 인용함
     │
  diagnose   단일 도구군 천장               ← 여기가 벤치마크 탈락 지점
     │       전체와 같으면 계획 문제가 아님
     │
  oracle     V*/Q*/최적집합                 probe가 예측할 타깃이 생김
     │
  embed      동결 인코더 캐시 (GPU 1회)      이후 모든 단계가 재사용
     │
  probe      ─────────── RQ1 ───────────   여기서 논문 절반이 나옴 (모델 학습 없이)
     │
  geometry   거리 5종 + 조절변수            C4
     │
  train_*    거리 헤드 · flow (<1M 파라미터)
     │
  ladder     ─────────── RQ2 ───────────   k-커밋 곡선 + blind 통제
     │
  report     주장 → 판정                    임계값이 아니라 CI·귀무분포로만
```

**1~6단계는 모델을 학습시키지 않습니다.** 학습이 안 되더라도 여기까지의 표는 그대로 논문에 들어갑니다.

## 8. 실패해도 무엇이 남는가

이 설계의 핵심입니다. 모델이 안 되어도 결과가 남는 경로가 일곱 개 있습니다.

| 관측 | 남는 결과 |
|---|---|
| 동결이 정합 통제를 못 이김 | **1차 결론의 실데이터 확인.** 이 측정 자체가 문헌에 없음 |
| 정보가 표면 절차뿐 | frozen 표현이 agent에서 하는 일이 생물학이 아니라는 **식별 결과** |
| 처음부터 학습이 동결을 따라잡음 | 이 계열 전체의 전제가 이 도메인에서 약하다는 결과 |
| DNABERT-2·SapBERT가 실데이터에서도 바닥 | 1차 붕괴가 합성 데이터 탓이 아니었다는 확증 |
| k 곡선 최적이 k=1 | **계획 생성 무용론의 도메인 증거.** 선행 두 편과 같은 방향 |
| 거리 헤드를 빼도 차이 없음 | `Geo`가 값을 못 한다는 명확한 결과. LeFlow 설계의 독립 확인 |
| 오염 홀드아웃에서 급락 | 이 분야가 동결 인코더로 유전학 벤치마크를 만들 때 인용할 숫자 |

**그리고 어떤 경우에도 벤치마크가 남습니다** — 실제 임상유전학 도구 + 전문가 단계 정답 +
점수 기반 단계별 성과 + 오염 통제 분할. 문헌에 이 조합은 존재하지 않습니다
(FlowBench는 단계 정답이 있으나 임상 변이해석이 없고, VariantBench는 임상 변이해석이나 종점 채점만).
